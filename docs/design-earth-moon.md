# 本物の地球と月 設計

状態: 段階1・2・3・5・6 を実装済み。段階0 は土地被覆のマップだけまだ (入手に NASA Earthdata のアカウントが要る) なので、段階4 は待ち。2026-11-23

出発地の TERRA と LUNA の表面を、本物の地球と月に近づける。
大陸・山脈・海の形と月の表側の模様は本物の観測データから作り、それより細かい部分は今のノイズで足す。
ゲーム縮尺 (半径 400 km / 110 km) と実寸 (6,371 km / 1,737 km) の両方で同じ仕組みを使う。

**今の地形の作りに素直に載せる。** 地形は「球に合わせて広げる大きな模様」と「m 単位の大きさを保つ細かい模様」に
分かれている (`docs/design-real-scale.md` の3章)。観測データは大きな模様の層だけを置き換え、細かい模様はそのまま使う。
ほかの天体とランダムな星系は1つも変えない。

## 1. 何を本物にするか

| 天体 | 本物にするもの | データ | 今のまま残すもの |
|---|---|---|---|
| TERRA | 標高 (陸と海底) | 全球の標高・水深 | 細かい起伏、岩と木の散らばり方、大気、水面 |
| TERRA | 地表の種類 (砂漠・草原・森・ツンドラ・氷) | 全球の土地被覆 | 色の細かいむら、雪の付き方 (標高と緯度) |
| TERRA | 夜の街明かり | 夜の地球の衛星画像 | |
| TERRA | 雲 (本物の天気ではなく、それらしい雲) | なし (ノイズで作る) | |
| LUNA | 標高 | 月の全球の標高 | マップより小さいクレーター、岩の散らばり方 |
| LUNA | 明るさ (暗い「海」と明るい高地) | 月の全球の画像 | |
| LUNA | 潮汐ロック (いつも表側を TERRA に向ける) | なし | |

## 2. データ

### 2.1 出典 (段階0 で使用条件を確かめてから取り込む)

| 用途 | 候補 | 元の解像度 | 使用条件の見込み |
|---|---|---|---|
| 地球の標高・水深 | NOAA ETOPO 2022 | 15〜60 秒角 | 米国政府の作成物でパブリックドメイン |
| 地球の土地被覆 | NASA MODIS MCD12C1 (IGBP 区分) | 0.05° (7200×3600) | NASA のデータで自由に使える |
| 地球の夜の明かり | NASA Black Marble (2016) | 約 500 m | 自由に使える。出典の表記を求められる |
| 月の標高 | NASA LRO LOLA の全球 DEM、または NASA SVS の CGI Moon Kit | 数十 m〜 | パブリックドメイン。CGI Moon Kit は出典の表記を求められる |
| 月の明るさ | NASA LRO LROC WAC の全球モザイク、または CGI Moon Kit の色マップ | 100 m〜 | 同上 |

- 使用条件はデータごとに必ず元のページで確かめる。「出典を書く」ものは README と `assets/maps/README.md` に書く。
- 元のデータは大きすぎる (数 GB) ので、変換の道具で縮めて、出来上がったファイルだけをリポジトリに入れる (2.3)。

### 2.2 解像度と容量

正距円筒図法 (横が経度、縦が緯度。横:縦 = 2:1) の格子で持つ。

| マップ | 大きさ | 1 画素の型 | 生の容量 | gzip 後 (見込み) |
|---|---|---|---|---|
| 地球の標高 | 4096×2048 | Int16 (m) | 16 MB | 5〜8 MB |
| 地球の土地被覆 | 4096×2048 | Uint8 (区分の番号) | 8 MB | 0.5〜1 MB |
| 地球の夜の明かり | 4096×2048 | Uint8 (明るさ) | 8 MB | 1〜2 MB |
| 月の標高 | 2048×1024 | Int16 (m) | 4 MB | 1.5〜3 MB |
| 月の明るさ | 2048×1024 | Uint8 | 2 MB | 1 MB |

1 画素の大きさ (赤道で):

| マップ | ゲーム縮尺 | 実寸 |
|---|---|---|
| 地球 (4096 幅) | 約 610 m | 約 9.8 km |
| 月 (2048 幅) | 約 340 m | 約 5.3 km |

どちらの縮尺でも大陸・山脈・大きなクレーターの形には十分。それより細かい部分はノイズで足す (3.3)。

### 2.3 ファイルの形と変換

- 置き場所は `assets/maps/`。例: `earth-height.bin.gz`、`earth-cover.bin.gz`、`earth-lights.bin.gz`、`moon-height.bin.gz`、`moon-albedo.bin.gz`。
- 中身は「小さな見出し (幅・高さ・型・値の倍率と足す値) + 画素の並び (北から南へ、経度 −180° から東へ)」をそのまま gzip したもの。
  ブラウザの `DecompressionStream('gzip')` で展開する (Worker の中でも使える)。画像形式 (PNG) は 16 bit を正しく読み出せないので使わない。
- 変換の道具は `tools/maps/` に置く (Python。縮小、型の変換、見出しを付けて gzip)。リポジトリには変換後のファイルだけを入れるので、
  Python のない開発機でもゲームは動く。道具の使い方とデータの入手先を `assets/maps/README.md` に書く。
- GitHub の 1 ファイルの上限 (100 MB) には十分収まる。GitHub Pages でもそのまま配れる。

## 3. 地形の作り方

### 3.1 緯度経度とローカル座標 (鏡写しにしない)

惑星のローカル座標は Y が自転軸 (北が +Y)。自転は Y 軸まわりの正の回転 (`planet.js` の `updateRotation`) で、
北極の上から見て反時計回り。これは本物の地球と同じ向きで、地表は +X から −Z の向きへ動く。地表が動く向きが東なので、

```
ローカル = (cos φ · cos λ,  sin φ,  −cos φ · sin λ)     φ: 緯度 (北が正)、λ: 経度 (東が正)
λ = atan2(−z, x)、 φ = asin(y)
```

とする。符号を間違えると、地図が左右反対になり、太陽が西から昇る。

- 変換は `src/terrain/geo.js` (three.js に依存しない) の `geoToLocal` / `localToGeo` に1か所でまとめる。
- 今の `debug.goto(alt, lat, lon)` と哨戒隊の位置 (`combat.js`) は `z = +cos φ · sin λ` で計算していて、
  経度の向きが逆 (西経) になっている。どちらも `geo.js` を使うように直す。
  ほかの天体はノイズの地形なので、向きが変わっても困らない (哨戒隊の場所だけ選び直す。8章)。

### 3.2 マップを読む (`src/terrain/maps.js`)

three.js にも DOM にも依存しない (Worker からも読むため)。

- `loadMap(name)`: `assets/maps/<name>.bin.gz` を読み込んで展開し、縮小版を重ねたもの (ミップマップ。1/2、1/4、… を前もって平均して作る) を
  用意して、同じ名前は使い回す。Promise を返す。
- `getMap(name)`: 読み込み済みならそれを、まだなら `null` を返す (待たない)。
- `registerMap(name, map)`: テストで小さな作り物のマップを登録する。
- 読む関数 `map.sample(φ, λ, cell)`: `cell` (m) は欲しい細かさ。それに合う縮小版を選んで読む。
  標高は 4×4 の画素から滑らかにつなぐ (双三次補間)。2×2 の直線補間だと、低空で画素の格子に沿った折れ目が見える。
  経度は ±180° でつなぎ、緯度は極で止める。
  土地被覆は区分の番号なので補間せず、最も近い画素を取る (境目は3.5 で揺らす)。

**粗いメッシュでは粗い縮小版を読む。** 遠くのチャンクの頂点が細かい画素を点で拾うと、場所ごとにでこぼこに当たり外れが出る。
`height(x, y, z, minWL)` の `minWL` から縮小版を選べば、今の「細部を省いても大きな形は変わらない」性質がそのまま保たれる。

### 3.3 標高の重ね方

TERRA と LUNA の地形の定義に、マップの名前を足す (名前だけなので Worker に渡しても軽い)。

```js
terrain: { type: 'terran', maps: { height: 'earth-height', cover: 'earth-cover' }, heightScale: 1 }
```

`makeTerrain` は `terrain.maps.height` があれば、`height()` の大きな模様の層 (ドメインワープ・大陸・山脈のマスク) を
マップに置き換える。

```
h = マップの標高 × heightScale + 細かい模様 (マップの画素より細かい波長だけ)
```

- **細かい模様は、マップの画素より細かい波長だけを足す。** 区切りの波長は `2 × (2πR ÷ マップの幅)`
  (ゲーム縮尺の地球で約 1.2 km、実寸で約 20 km)。区切りより長い波長のオクターブは足さない。
  こうすると、本物の山の形をノイズが書き換えず、縮尺によらず同じ規則で決まる
  (ゲーム縮尺ではマップがほとんどを決め、実寸では尾根のノイズの一部が残ってヒマラヤに細かい尾根が付く)。
  オクターブを途中から始める仕組みを `ridged` / `fbmEroded` / `fbm` に足す。
- **山脈のノイズのマスク** は、今の低周波のノイズではなく、マップの標高と傾きから作る (高くて起伏のある所ほど尾根を足す)。
- **海岸**: 細かい模様が海面をまたぐと小さな島や池が散らばるので、マップの標高が 0〜50 m の所では細かい模様を弱める。
  海底には細かい模様を足さない (今の海洋惑星と同じ)。
- **渓谷と台地** (`CLIFFS`) は、本物の地形の上では作り物に見えるので、マップのある天体では切る (`canyons: 0, mesas: 0`)。
- **クレーター** (LUNA): 区画の一辺が区切りの波長より大きい層は足さない。大きなクレーターはマップにすでにある。
- 海面より低い陸 (カスピ海の周り、死海、オランダの干拓地など) は今の規則のまま水面になる。カスピ海と死海は本物も水があるので
  そのままでよい。ほかは小さいので気にしない。

### 3.4 高さの倍率

| 天体 | ゲーム縮尺 | 実寸 |
|---|---|---|
| TERRA | 1 (本物の高さ) | 1 |
| LUNA | 0.4 (推。12章) | 1 |

- 地球は今も山の高さが本物に近い (最高 6,200 m 前後) ので、本物の高さ (エベレスト 8,849 m、海溝 −10,900 m) をそのまま使う。
- 月は本物の起伏が約 20 km ある。ゲーム縮尺の LUNA (半径 110 km) でそのまま使うと、半径の 2 割近い凹凸になって見た目が崩れる。
  今の規則 (`makeBody` は起伏を「ゲーム縮尺の半径 ÷ 400 km」倍する) に近い値に縮める。

### 3.5 地表の色と植生 (TERRA)

今の `colorTerran` は、湿り気のノイズと緯度・標高で色を決めている。これを土地被覆の区分で決めるように変える。

| 区分 (IGBP をまとめたもの) | 色 | 木 (`forest()`) |
|---|---|---|
| 熱帯の森 | 濃い緑 | 多い |
| 温帯の森、針葉樹林 | 緑、暗い緑 | 多い |
| 低木地、草原、サバンナ | 黄緑〜枯れ草色 | 少し |
| 農地 | 明るい緑と茶色のまだら | 少し |
| 砂漠、裸地 | 砂色〜赤茶色 | なし |
| ツンドラ | 灰色がかった茶色 | なし |
| 雪と氷 (南極、グリーンランド) | 白 | なし |
| 都市 | 灰色 | なし (街明かりは 4章) |

- 区分の境目が画素の形 (カクカクした段) に見えないよう、読む位置をノイズで少しずらす (ドメインワープ)。
- 木の配置 (`forest()`) も同じ区分から決める。今の「色と木の範囲を揃える」性質を保つ。
- 雪は今と同じく標高と緯度でも付ける (高い山の雪)。急斜面の岩、砂浜の規則もそのまま。

### 3.6 月の色

- 今の岩石天体は「標高 0 以下を暗い平原 (月の海) にする」。月の標高マップは基準の半径からの高さなので、この規則を切り、
  明るさのマップで暗い海と明るい高地を決める。
- マップより小さいクレーターは今のまま足す。若いクレーターの白い放射状の筋は、マップに入っているもので足りる。

## 4. 夜の街明かり (TERRA)

- 夜の明かりのマップを GPU のテクスチャ (`DataTexture`、R8) にして、地表のシェーダーで読む。
  頂点の色に入れると、低空でぼやけた大きな塊になるため。地形の Worker には関係しない。
- シェーダーは惑星ローカル座標から緯度経度を求めて読む (3.1 と同じ式)。
  都市惑星の `cityLights` の「夜側だけ光る」「暖かい色」の部分を流用する。
- 近づいたときは、明かりの濃さをノイズで細かい点に分け、一様にぼやけた光に見えないようにする。

## 5. 雲 (TERRA)

本物の天気のデータは使わず、ノイズで作る。

- **球のメッシュでは作らない。** 実寸では球を多角形で近似したへこみが数 km になり、雲の層 (高度 2〜10 km) が地面や機体と食い違う
  (ガス巨星を LOD で描くようにしたのと同じ理由。`docs/design-real-scale.md` の5章)。
  空のシェーダーと地表のシェーダーの中で、視線と「雲の層の球」の交点を計算して描く。
- 空のシェーダー: 視線が雲の層を通る所で雲の濃さを求め、太陽光で照らして空に重ねる。雲の下から見上げても、上から見下ろしても同じ計算。
- 地表のシェーダー: カメラと地表の間に雲があれば手前に重ね、地表の点から太陽の向きに雲があれば影にする。
- 雲の濃さは、時間で流れる数オクターブのノイズに、緯度ごとの量 (赤道付近と中緯度に多く、亜熱帯の砂漠帯に少ない) を掛ける。
- 当たり判定はない。機体は雲をすり抜ける。

## 6. 潮汐ロック (LUNA)

- 惑星は公転しないので、「公転と同じ周期で自転する」は「自転しない」と同じになる。天体の定義に `tidalLock: true` を足し、
  そのときは自転の角速度を 0 にする。`rotationPeriod` は数字のまま残す (星図などで使う)。
- 自転の最初の向き `rotationPhase` (Y 軸まわりの角度) を足す。LUNA の表側の中心 (緯度 0°・経度 0°) が TERRA を向くように、
  `system.js` で TERRA の方向と自転軸の傾きから計算する (three.js を使わない)。
- 太陽の向きも動かないので、月の満ち欠けは止まったまま。どの形に見えるかは、今の LUNA の置き場所と太陽の向きで決まる
  (置き場所は変えない。表側がどれだけ昼になるかは段階2 で確かめる)。
- TERRA にも `rotationPhase` を使い、開始時に見える地域を選ぶ (12章)。

## 7. 読み込みの流れ

今の `makeTerrain` は、呼ばれたその場で地形関数を作る (メインスレッドの接地判定と Worker の両方)。マップは読み込みを待つ必要がある。

- **開始前に読み込む。** マップを使うのは SOL だけなので、`main.js` で `Game` を作る前に、SOL のマップを読み込んで待つ
  (読み込み中は画面に「地形データを読み込み中」と出す)。縮尺の切り替え (`setScale`) とやり直し (`restart`) も SOL なので、待つのは最初の1回だけ。
- **Worker は自分で読み込む。** チャンクの依頼に来た `def` にマップの名前があり、まだ読んでいなければ、読み込んでから作る
  (`onmessage` を `async` にする)。大きな配列を依頼のたびに送らずに済む。
- **`makeTerrain` は待たない。** マップの名前があるのに読み込まれていなければ、例外を投げる (読み忘れにすぐ気づけるように)。
- **読み込めなかったとき** (ネットにつながっていないなど): メインスレッドが TERRA と LUNA の定義からマップの名前を外し、
  今のノイズの地形で始める。Worker にはマップの名前のない定義が渡るので、接地判定と見た目は食い違わない。
  画面に「地形データを読み込めなかった」と出す。
- **他の星系へ行ったとき**: Worker の地形関数の置き場 (`terrains`) は今は増える一方なので、星系を移ったら古いものを捨てる仕組みを足す。
  マップ自体は SOL に戻るときのために残す。

### メモリ

- Worker は 2〜6 個 (`planetLod.js`)。SharedArrayBuffer は、必要なヘッダーを GitHub Pages で付けられないので使えない。
  そのため各 Worker とメインスレッドが、それぞれマップの写しを持つ。
- 地球の標高 (16 MB) + 土地被覆 (8 MB) + 月の標高 (4 MB) + 明るさ (2 MB) と縮小版 (+1/3) で、1 つあたり約 40 MB。
  最大 7 つで約 280 MB になる。
- 多すぎるときの手: (1) Worker は今いる天体のマップだけを読む (地球か月の片方だけで済む) (2) 土地被覆を 2048 幅にする
  (3) 夜の明かり・月の明るさは GPU 側だけで持つ (Worker は読まない)。(3) は最初から行う。段階7 で実際に測って決める。

## 8. 開始地点と哨戒隊

- 開始地点は今のまま (TERRA から半径の約 8.4 倍)。TERRA の `rotationPhase` で、開始時に TERRA の昼側に見える地域を決める。
- TERRA 上空の哨戒隊 (今は北緯 20°・東経 30°。本物の地図ではエジプトの砂漠になる) は、本物の地名で選び直す (12章)。
- LUNA は表側が TERRA を向くので、開始地点からは表側の模様 (暗い海) が見える。

| 7 | 調整: メモリと読み込み時間を測る、README・マニュアル・仕様書・技術解説ページ・CLAUDE.md を直す | 7章のメモリの手を決め、文書が実装と合う |

- 段階2 を地球より先にするのは、海も植生もない月で読み込みの仕組みを先に確かめるため。
- 段階5 と 6 は描画だけで、地形の Worker と当たり判定には関係しない。段階3・4 と並べて進めてもよい。

## 10. この設計に含めないこと

- 海面より高い湖と川 (五大湖、バイカル湖、大河)。標高のマップには水面の高さが入っていないので、くぼ地として乾いたまま見える。
  あとで水域のマップを足して扱える
- 本物の天気・雲の動き、季節、海流
- 惑星の公転と月の満ち欠けの変化 (`docs/design-real-scale.md` の10章と同じ)
- 他の天体の本物の地形 (火星の MOLA、水星など)。この仕組みでマップを足すだけで作れるので、別の段階で考える
- 本物の都市の建物 (街明かりだけにする)

## 11. テスト

新しいテストは `tests/m15.test.js` に書き、`tests.html` に1行足す。

- **緯度経度**: `geoToLocal` と `localToGeo` が互いに逆。経度 ±180° と極でつながっている
- **東から昇る**: TERRA の自転を進めると、太陽の真下の経度が減っていく (太陽が東から西へ動く)
- **マップを読む** (作り物のマップ): 画素の中心で値がそのまま出る。経度の継ぎ目と極で値が連続している。粗い縮小版の値が細かい版の平均と合う
- **重ね方**: 画素より粗い `minWL` では、標高がマップの値 × `heightScale` と一致する (細かい模様が大きな形を変えない)。
  細部を省いても大きな形は変わらない (今の LOD のテストと同じ形)。海岸の近くで細かい模様が弱まる
- **本物の地形** (実際のマップ): エベレスト付近が 5,000 m より高い、太平洋の真ん中が −3,000 m より深い、日本が陸、
  サハラが砂漠の区分、アマゾンが森の区分、南極が氷の区分。両方の縮尺で同じ地点の標高が同じ (× 倍率)
- **潮汐ロック**: どの時刻でも LUNA の表側の中心が TERRA を向いている。両方の縮尺で同じ
- **読み込めなかったとき**: マップの名前を外した定義が今のノイズの地形と同じになる
- **今のテスト**: M1〜M14 が通る。直すのは `m5` の「TERRA の `terrain === null`」の1か所だけの見込み
  (`m14` の地形の比較は seed 2024 のノイズの地形そのものを使うので変わらない)

## 12. まだ決めていないこと

既定値として推したものを書いてあり、好みで変えてよい。

- **ゲーム縮尺の月の高さの倍率**: 0.4 を推す (起伏が最大で約 8 km)。遊んで決める
- **開始時に見える TERRA の地域**: 日本付近を昼側にするのを推す
- **TERRA 上空の哨戒隊の場所**: 開始時に見える地域の上空 (日本付近なら関東平野の上空) を推す
- **土地被覆のデータ**: MODIS (区分がはっきりしていて、パブリックドメイン) を推す。気候区分 (ケッペン) から作る手もある
- **地球の標高マップの大きさ**: 4096 幅を推す。メモリが厳しければ 2048 幅にする (ゲーム縮尺で 1 画素約 1.2 km)
- **雲の量**: 本物の地球に近い、空の約 6 割を推す。地表が見えにくければ減らす
