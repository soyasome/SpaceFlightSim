# オニール・シリンダー 設計 (シンプル版)

状態: 設計のみ (未実装)。2026-11-21

円筒形の宇宙居住地。中に入って、内側の地面に着陸できる。
惑星と違い、内側の地面が「上」にも見える。軸の近くでは重力がほぼゼロになる。

**回っているのは見た目だけにする。** 外から見ると円筒は回っているが、中の物理は回らない座標系で計算し、
重力は「軸から外向き」に直接かける。遠心力とコリオリ力は計算しない。
後で回転の物理を足すときに変える所は、11章にまとめてある。
後で作るリングワールドも、同じやり方で作れる。

## 1. 寸法と物理

O'Neill の Island Three と同じ大きさにする。惑星はゲームの都合で小さくしてあるが、
これは人間の大きさの構造物なので縮めない。

| 項目 | 値 | 備考 |
|---|---|---|
| 半径 R | 4,000 m | 直径 8 km |
| 長さ L | 32,000 m | |
| 内部の重力 | 軸から外向きに g · r / R (g = 9.81 m/s²、r = 軸からの距離) | 軸では 0、地面で 1 g |
| 空気の密度 | 地面で 1.2 kg/m³、軸で約 0.79 倍 | ρ(r) = ρ₀ exp(g (r² − R²) / (2R · 287 · 288)) |
| 見た目の回転 | 約 127 秒で1回転 | 外から見たときだけ。地面で 1 g になる本来の速さ (√(g/R)) |

- 内側の周を6等分し、**陸の帯3本と窓の帯3本**を交互に並べる。1本の帯の幅は 60° (約 4.2 km)。
- 窓の外側には**鏡**が3枚ある。恒星の光を窓から中へ入れる。鏡の角度を変えて昼と夜を作る。
- 軸は恒星の方を向ける。恒星側の端は発電所と農業の環、反対側 (影の側) の端には**入港口**を置く。
- 逆向きに回る**2本1組**で置き、両端を骨組みでつなぐ。2本は同じクラスで作るので、どちらにも入れる。

## 2. どこに置くか

- **出発地 SOL**: TERRA のラグランジュ点 L5 (TERRA の位置を恒星のまわりに -60° 回した所) に1組置く。
  開始位置から約1天文単位で、巡航で約2分。名前はほかの天体に合わせてラテン語の `INSULA I / II`。
  TERRA との位置関係は変えないので、M1〜M4 のテストは変わらない。
- **都市惑星のある星系**: 都市惑星の L4 か L5 に1組置く (別の乱数で決める)。
- `system.js` の戻り値に `habitats: [{ key, name, position, axis, radius, length, spin: ±1, seed }]` を足す。
  星図・ナビ・巡航の減速 (惑星と同じく、外壁までの距離を `cruiseDist` に入れる) は、惑星と同じ扱いにする。

## 3. 座標系と物理

### 中の座標系

- 円筒の中では、円筒に固定された座標系で機体を動かす (原点 = 円筒の中心、ローカルの Y 軸 = 円筒の軸)。
  **この座標系は回らない。** 惑星の座標系 ([frame.js](../src/physics/frame.js)) で自転の角速度を 0 にしたものと同じで、
  `enterFrame` と `leaveFrame` は位置と向きを変換するだけになる (速度の変換はない)。
- 重力は、軸から外向きに g · r / R をかける。遠心力とコリオリ力は計算しない。
  - 軸の近くでは浮き、地面に近づくほど重くなる
  - 機体の操縦系は重力の向きを `env.gravity` から求めているので、ホバー・揚力・G の計算は変えなくてよい
- 外から見た円筒の回転は、外観のメッシュを回すだけ。中から窓越しに見える星空は止まっている。

### 出入りの境目

- 座標系に入るのは、**円筒の中にいるときだけ** (軸からの距離 < R かつ |y| < L/2。入港口の筒の中も含む)。
  外にいる間は世界座標のまま。
- 中への入口は、影の側の端の軸上にある入港口だけ (外壁と両端の蓋は壁なので)。
- 座標系に入ると、巡航は自動で解除する。中では巡航を使えない。

## 4. 惑星と円筒の共通の窓口

今のコードは「下 = 惑星の中心の方」を前提に、あちこちで `pos.length()` や `groundRadiusAt` を使っている。
円筒では下は軸から外向きなので、`game.frame` が持つ窓口を次のように一般化する。
**作業の大部分はここ**で、回転させるかどうかに関係なく必要になる。

| メソッド | 惑星 | 円筒の内側 |
|---|---|---|
| `contains(p)` / `shouldExit(p)` | 中心からの距離と `frameEnter` / `frameExit` を比べる | 円筒の中か (入港口の筒を含む) |
| `upAt(p, out)` | p / \|p\| | −(x, 0, z) / r |
| `heightAbove(p)` | \|p\| − `groundRadiusAt(p)` | (R − h(θ, y)) − r |
| `groundPointAt(p, out)` | 真下の地面の点 | 軸から外へ伸ばした線と地面の交点 |
| `gravityAt(p, out)` | 中心へ g(r) | 軸から外へ g · r / R |
| `densityAt(p)` | 高度で決まる | ρ(r) |
| `seaLevelAt(p)` | \|p\| − radius | (表示用) 軸からの距離 |

**直すところ**:
- [ground.js](../src/flight/ground.js)
  - `groundNormal` は、真下の点のまわりを `upAt` に直交する2方向に調べる
  - 崖の二分探索は `heightAbove < 0` で判定する
- [game.js](../src/game.js)
  - 高度、上昇率、静止摩擦の判定 (`normal · up > 0.82`)、カメラが地面にもぐらない処理、`placeShip`、復帰する場所
  - HUD の水平線と方位: 上は `upAt`。円筒の「北」は軸の +Y (恒星側) にする
  - `envAt` は `gravityAt` と `densityAt` を呼ぶだけにする
- [combat.js](../src/combat/combat.js): `altitudeAt`、`upAt`、`solidHit` を窓口経由にする

**最初の段階では惑星だけをこの窓口に移し、動きを変えないこと** (テストが全部そのまま通ること) を確かめてから、円筒を足す。

## 5. 中の地形と描画

### 地形

- 標高 h(θ, y) (m) は陸の帯だけ。ノイズは (R cos θ, R sin θ, y) の3次元で引くので、θ = 0 と 2π の継ぎ目が出ない。
  - 起伏は小さく (±60 m 程度)、丘・湖・帯に沿って流れる川・町を置く
  - 帯の両端 (窓との境) は土手にする
  - 両端の蓋に近づくほど地面が上がり、段々畑の山になって蓋の壁につながる
- 窓の帯は h = 0 の平らなガラス。着陸もでき、当たり判定は地面と同じ。
- 地形のメッシュ: (周方向の距離 s = θR, y) の平面を四分木の LOD で区切る。根は 4 × 5 枚
  (1枚 約 6.3 km × 6.4 km)。チャンクは Worker で作り、`chunkBuilder` の仕組みをまねる。
  座標は最大でも十数 km なので float32 で足り、基準点の工夫はいらない。
- 木と家: [scatter.js](../src/planet/scatter.js) はキューブ球に固定されているので、(s, y) の格子で区画を切る小さな版を作る。
  形とマテリアル (木、ビル) は使い回す。

### 光と空

- 惑星の大気散乱のシェーダーは球が前提なので使わない。円筒用に「地表の色 + 光 + 距離による霧」の簡単なマテリアルを作る。
- 陸の帯は、向かい側の窓から入る鏡の光で照らす。光の向きはおおよそ「真上」で、鏡の角度に応じて軸の方向へ傾ける。
  - 朝夕は低い角度から差し込み、夜は鏡を閉じて光がなくなる
  - 1日は 24 分 (ゲーム内の時間)
  - 夜は都市惑星の街明かりのシェーダー (`cityLights`) を使い回して、町を光らせる
- 見上げると、霧にかすんだ向こう側の陸の帯 (8 km 先) と窓が見える。
  窓は半透明のガラスと骨組みで、外の星空と鏡に映った恒星が見える。恒星そのものは軸の方向にあるので、窓からは直接見えない。
- 霧は距離に応じて薄い青にする (32 km 先の反対の端は、ほとんど見えない)。

## 6. 外観

- 外壁 (長い円筒) と、3本の窓 (中の光が漏れる)、窓の外に開いた3枚の鏡を置く。
- 恒星側の端には農業の環と発電所の皿、影の側の端には入港口と入港の筒を置く。
- 2本の円筒は逆向きに回して見せ (メッシュを回すだけ)、両端を骨組みでつなぐ。
- 遠く (見かけが数ピクセル) では HUD の目印だけにする。近づくと形が見える (惑星と同じく `group` の位置と向きを毎フレーム置く)。

## 7. 当たり判定

物理の上では円筒は止まっているので、どの壁も止まった面として扱う。

| 場所 | 扱い |
|---|---|
| 中の地面と窓 | 惑星と同じ接地の処理 (脚・機体の各点)。着陸できる |
| 両端の蓋 (中から) | 壁として押し戻す。速いと損傷。崖と同じく、点ごとに調べる |
| 入港口の筒の壁 | 同上 (円筒の内側の壁) |
| 外壁 (外から) | ダイソン・スウォームのパネルと同じく、押し戻して跳ね返す。外には重力がないので着陸はしない |
| 鏡・骨組み | 最初は当たらない (後の段階で、パネルと同じ板の判定を足す) |

## 8. ゲームとしての扱い

- 中は**安全地帯**。敵の哨戒隊は置かず、追ってきた敵も入港口の前で引き返す。
- 出発地 SOL に置くので、最初の目的地になる。中の宇宙港 (平らな着陸パッド) に降りる。
- 軸の近くは重力がほぼない。上へ飛ぶほど体が軽くなり、軸を越えると向かい側の地面が「下」になる。
- 中で機体を失ったら、宇宙港の上空に復帰する。
- HUD:
  - `ALT` は地面からの高さ
  - `SEA LEVEL` の代わりに、軸までの距離と、その場所の重力 (例: `0.42 G`) を出す
  - 水平線は `upAt` の向きで描く

## 10. テスト

- **窓口の共通化**: 惑星について、新しい窓口の値が今の値 (`groundRadiusAt`、重力、密度) と一致する
- **重力**: 地面では 1 g、軸では 0、半径 r では g · r / R。向きは軸から外向き
- **座標系**: 入って出ると元の状態に戻る (今の座標系のテストと同じ)。円筒の外では座標系に入らない
- **地形**: θ = 0 と 2π の継ぎ目で標高が連続。陸と窓が 60° ごとに交互に並ぶ
- **着陸**: 静かに降ろすと3本の脚で止まる (M3 の着陸テストを円筒で)
- **壁**: 蓋の壁に突っ込むと、壁で止まって壊れる
- **配置**: SOL の L5 にあり、TERRA や開始位置の配置は変わらない。都市惑星の星系の円筒は、惑星の座標系と重ならない

## 11. 後で回転の物理を足すとき

シンプル版で省いたものと、足すときに変える所。

| 省いたもの | 足すときに変える所 |
|---|---|
| 中の座標系の回転 | 座標系の角速度を 0 から √(g/R) にする。`enterFrame` / `leaveFrame` が速度を変換するようになる |
| 遠心力 | `gravityAt` の g · r / R を ω² r に置き換える (地面での値は同じ) |
| コリオリ力 | `gravityAt` に速度 v を渡し、−2 ω × v を足す。100 m/s で約 1 g 横に流されるので、強さを設定で選べるようにする |
| 窓から見える星空の回転 | 座標系が回れば自然に回る (今と同じく、星空に座標系の逆回転をかけるため) |
| 外壁が動いていること | 外から当たったとき、外壁の速さ (198 m/s) を考えて跳ね返す |

テストには「外から見て止まっている物を中から追うと、回転を戻したときに止まったままになる」を足す。

## 12. まだ決めていないこと

既定値として推したものを書いてあり、好みで変えてよい。

- **大きさ**: 実物どおり (半径 4 km) を推す。広く飛び回りたいなら、2倍 (半径 8 km) にもできる
- **重力の分布**: 軸からの距離に比例 (g · r / R) を推す。どこでも 1 g にもできるが、軸の近くで浮く楽しさがなくなる
- **SOL に置くか**: 置くのを推す (最初の目的地になる)。置かない場合は、都市惑星の星系だけになる
